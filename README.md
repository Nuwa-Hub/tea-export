# 🍃 Tea Export Forecasting & Readiness

A starter scaffold for the research project
**"AI-Powered Tea Export Decision Support for Sri Lanka."**

This first stage implements the pipeline **up to the Export Readiness Index**:

```
CSV data  ->  TRAIN once (saved LSTM models)  ->  forecasts (price / volume / FX)  ->  Export Readiness Index
```

- **Backend** — FastAPI + TensorFlow/Keras LSTM (univariate, multi-step) + a
  weighted Export Readiness Index engine.
- **Frontend** — React (Vite), two tabs: a **Train Models** page and a
  **Dashboard** (forecast charts, back-test accuracy, Export Readiness Index).

**Two-stage design (important):** training is separate from forecasting.

1. **Train once** (Train Models tab → `POST /api/train`): fits one LSTM per
   series and **saves them to disk** (`backend/models/*.keras` + scalers).
   This is the only slow step (~30s).
2. **Forecast many** (Dashboard): just **loads** the saved models, so it
   responds in ~1s. Changing the horizon does **not** retrain.

> The data is **sample/synthetic** and lives in a file — `backend/data/tea_export.csv`
> (also `.xlsx`). Regenerate it with `python -m app.data`, or replace it with
> real Sri Lanka Tea Board / Central Bank data (same columns) — nothing else changes.

## Run the backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# from the backend/ directory:
uvicorn app.main:app --reload --port 8000
```

API docs (Swagger) at <http://localhost:8000/docs>. Key endpoints:

| Endpoint | Purpose |
|---|---|
| `GET /api/health` | liveness (+ whether models are trained) |
| `GET /api/history` | the raw monthly dataset (from CSV) |
| `GET /api/model-status` | are models trained? when? with what accuracy? |
| `POST /api/train` | **train + save** all LSTMs (the slow, once-only step) |
| `GET /api/forecast?horizon=6` | LSTM forecasts + accuracy (needs trained models) |
| `GET /api/readiness?horizon=6` | Export Readiness Index only (needs trained models) |
| `GET /api/dashboard?horizon=6` | everything in one call (used by the UI) |

> The forecast endpoints return **HTTP 409** until you train. After `POST /api/train`
> the models are saved to `backend/models/`, and every forecast just loads them (~1s).

## Run the frontend

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

The dev server runs on port **5173**, which the backend's CORS config allows.

**First-time flow:** start the backend → open the app → **Train Models** tab →
click *Train models* (~30s) → switch to **Dashboard**. After that the dashboard
loads instantly; retrain only when the data changes.

## The Export Readiness Index (ERI)

`backend/app/readiness.py` turns the raw forecasts into a 0–100 decision score:

```
ERI = 0.40 * demand   (forecast export-volume growth)
    + 0.30 * price     (forecast auction-price trend)
    + 0.20 * exchange  (USD/LKR outlook — depreciation favours exporters)
    + 0.10 * stability (inverse of recent price volatility)
```

| Score | Status | Meaning |
|---|---|---|
| 80–100 | **Ready** | proceed with export planning |
| 60–79 | **Conditional** | viable, but monitor price/demand |
| < 60 | **Not Ready** | hold for better conditions |

The weights and component formulas are a defensible starting point — tuning and
validating them is a natural part of the research write-up.

## Where to take it next (per the road-map)

1. **Real data** — drop your own monthly file in as `backend/data/tea_export.csv`
   (same columns) and retrain — no code changes needed.
2. **ARIMA / ARIMAX baselines** — add `statsmodels` and compare MAE/RMSE/MAPE
   against the LSTM (the comparison is itself a research contribution).
3. **Multivariate LSTM** — feed price + volume + FX + weather together.
4. Later phases (RAG advisor, blockchain certification) build on top of this
   forecasting + readiness core.
